텍스트 비교(diff) 활용법: 계약서·원고·코드 수정 내용을 정확히 찾는 요령

두 텍스트의 차이를 줄 단위·단어 단위로 비교하는 원리와 diff 결과 읽는 법, 공백·줄바꿈·인코딩 때문에 가짜 차이가 생기는 원인, 문서 검토 때 비교 순서를 정리합니다.

작성·검토: 쓸모칸 운영자게시 2026-10-18 · 최종 수정 2026-10-18 · 읽는 시간 약 4분
핵심 요약
  • diff는 두 텍스트에서 같은 부분을 최대한 찾아내고 나머지를 추가·삭제로 표시하는 방식입니다.
  • 줄 끝 공백, 줄바꿈 형식(CRLF/LF), 따옴표 모양이 달라도 차이로 잡혀 실제 수정이 아닌 가짜 차이가 생깁니다.
  • 계약서나 제출 원고는 눈으로 대조하기보다 비교 결과를 확인한 뒤 변경 사유를 따로 기록하는 것이 안전합니다.

상대방이 "일부만 고쳤다"며 보낸 계약서 수정본, 팀원이 손본 원고, 여러 번 복사한 설정 파일은 눈으로 비교하면 놓치는 부분이 생깁니다. 텍스트 비교는 이런 변경을 기계적으로 찾아내는 가장 빠른 방법입니다. 결과를 제대로 읽으려면 비교가 어떻게 동작하는지 알아두는 편이 좋습니다.

1. diff는 어떻게 차이를 찾나

대표적인 방식은 두 텍스트에서 순서를 유지한 채 공통으로 나타나는 가장 긴 부분(최장 공통 부분 수열)을 찾고, 공통이 아닌 곳을 삭제와 추가로 표시하는 것입니다. 한 줄이 바뀌면 보통 "기존 줄 삭제 + 새 줄 추가"로 보입니다. 단어 단위 비교를 지원하는 도구는 한 줄 안에서 바뀐 단어만 강조합니다.

2. 결과 읽는 법

표시의미예시
초록·+새로 추가된 내용제8조 3항이 새로 생김
빨강·-삭제된 내용위약금 문구가 사라짐
강조된 단어한 줄 안의 일부 변경지급 기한 14일이 30일로 변경
변경 없음양쪽이 같은 부분검토할 필요가 적음

숫자·날짜·금액·기한·당사자 이름이 바뀐 곳은 문장 전체를 읽는 것보다 강조된 부분을 먼저 확인하세요. "30일"이 "3일"이 되는 식의 한 글자 변경이 가장 위험하면서 눈에 잘 띄지 않습니다.

3. 가짜 차이가 생기는 대표 원인

  • 줄 끝 공백·탭: 눈에 보이지 않는 공백이 달라도 다른 줄로 취급됩니다.
  • 줄바꿈 형식: Windows(CRLF)와 macOS·Linux(LF)의 줄바꿈이 달라 모든 줄이 바뀐 것처럼 나올 수 있습니다.
  • 따옴표·하이픈 모양: 문서 편집기가 자동으로 바꾼 둥근 따옴표(“ ”)나 긴 줄표(—)는 일반 문자와 다릅니다.
  • 자동 줄바꿈 위치: PDF에서 복사한 글은 문단 중간에 줄바꿈이 들어가 줄 단위 비교에서 전부 달라 보입니다. 먼저 줄바꿈을 정리한 뒤 비교하세요.
  • 한글 자모 분리: 일부 환경에서 복사한 한글이 자음·모음으로 분리된 형태(NFD)일 수 있어 겉보기에는 같은 글자가 다르게 인식됩니다.

4. 문서 검토 순서

  • 원본과 수정본을 명확히 구분합니다. 왼쪽을 이전 버전, 오른쪽을 새 버전으로 고정하면 추가와 삭제가 헷갈리지 않습니다.
  • 서식 차이는 정리 후 비교합니다. 공백 제거 기능이나 줄바꿈 정리를 먼저 적용하면 가짜 차이가 줄어듭니다.
  • 변경 목록을 따로 기록합니다. 조항 번호, 변경 전후, 요청한 사람을 적어 두면 나중에 합의 내용을 확인하기 쉽습니다.
  • 변경하지 않았다고 한 부분도 샘플로 확인합니다. 합의하지 않은 수정이 섞여 들어오는 경우가 있습니다.

5. 개인정보와 보안

계약서나 인사 문서처럼 민감한 내용을 온라인 서비스에 올려 비교하는 것은 외부 서버에 저장될 위험이 있습니다. 이 사이트의 비교 도구는 입력한 내용을 브라우저 안에서 처리하지만, 일반적으로는 어떤 도구를 쓰든 주민등록번호나 계좌번호는 가리고 비교하는 습관이 안전합니다.

6. 코드·설정 파일 비교

설정 파일은 항목 순서가 바뀌어도 의미가 같을 수 있습니다. JSON은 키 순서를 정렬한 뒤 비교하면 실제 값 변경만 남습니다. 형식이 깨지지 않았는지는 JSON 오류 가이드의 점검표로 확인하세요. 코드 변경 이력은 Git 같은 버전 관리 도구가 더 정확하므로 단발성 비교에만 이 방식을 쓰는 것을 권합니다.

자주 묻는 질문

줄 단위와 글자 단위 비교 중 무엇이 좋은가요?

구조가 있는 문서는 줄 단위로 큰 변경을 찾고, 한 줄 안의 수정은 단어 또는 글자 단위로 보는 순서가 효율적입니다.

대소문자만 다른 경우도 차이인가요?

기본값은 차이로 취급합니다. 영문 문서에서 대소문자를 무시하고 싶다면 비교 전에 한쪽을 소문자로 통일하세요.

이미지나 표가 들어 있는 문서도 비교되나요?

텍스트만 비교합니다. 표 서식과 이미지는 원본 편집기의 변경 내용 추적 기능으로 확인해야 합니다.
