도구를 불러오는 중입니다.

JSON 포맷터·검증기 사용 방법

JSON 문자열, 들여쓰기와 키 정렬 여부를 입력합니다.

결과에서 확인할 내용

문법을 검증해 정렬 또는 압축하며 오류 행과 열을 안내합니다.

이 도구가 필요한 상황

API 응답이나 설정 파일의 JSON 문법을 검사하고 들여쓰기·키 정렬·압축 결과를 만듭니다. 파싱에 실패하면 가능한 경우 오류 위치의 행과 열을 알려줍니다.

실제 사용 예시

마지막 속성 뒤의 불필요한 쉼표, 작은따옴표, 닫히지 않은 중괄호는 JSON 오류입니다. 검증 후 공백 2칸으로 정렬하면 코드 리뷰가 쉬워지고, 전송 전에는 압축해 크기를 줄일 수 있습니다.

결과를 정확히 읽는 방법

  • JSON은 주석, undefined, NaN, 작은따옴표 속성명을 허용하지 않습니다.
  • 키 정렬은 객체의 표시 순서만 바꾸며 배열의 항목 순서는 보존합니다.
  • 민감한 토큰이 포함된 데이터는 외부 검증기에 붙여넣지 말고 브라우저 처리 도구를 사용하는 편이 안전합니다.

계산 방식

JSON은 키와 문자열을 큰따옴표로 감싸고 값에 객체·배열·문자열·숫자·true·false·null만 허용하는 데이터 형식입니다. 포매터는 먼저 문법을 파싱해 오류가 없는지 확인하고, 통과하면 들여쓰기를 적용하거나(보기 좋게), 공백을 제거(압축)해 같은 데이터를 다른 모양으로 출력합니다.

상황별 계산 사례

  • {"name":"민수","tags":["a","b"],}처럼 마지막 속성 뒤에 쉼표가 있으면 JSON 문법 오류입니다. 쉼표를 지우면 정상 파싱됩니다.
  • 자바스크립트 객체처럼 {name:"민수"}라고 쓰면 키에 따옴표가 없어 오류입니다. JSON에서는 {"name":"민수"}여야 합니다.
  • 큰 정수 9007199254740993은 자바스크립트에서 9007199254740992로 읽혀 정밀도를 잃을 수 있습니다. 안전하게 다루는 정수 한계는 9,007,199,254,740,991입니다.
  • API 응답을 공백 2칸으로 정렬하면 변경 전후를 diff로 비교하기 쉬워지고, 전송 직전에는 압축해 크기를 줄일 수 있습니다.

자주 하는 실수

  • 주석(// 또는 /* */)을 넣는 실수: 표준 JSON은 주석을 허용하지 않습니다.
  • 작은따옴표로 문자열을 감싸는 실수.
  • undefined, NaN, Infinity를 값으로 쓰는 실수.
  • 토큰·비밀번호가 포함된 JSON을 외부 사이트에 붙여넣는 실수.

자주 묻는 질문

오류 위치가 정확히 안 나오는 경우도 있나요?

파서가 처음 문제를 만난 위치를 알려 주므로 실제 원인은 그 앞쪽(닫히지 않은 괄호 등)에 있는 경우가 많습니다.

키 정렬을 하면 배열 순서도 바뀌나요?

객체의 키 표시 순서만 바뀌고 배열 항목의 순서는 그대로입니다.

JSON과 JSON5는 같은가요?

JSON5는 주석과 작은따옴표 등을 허용하는 확장 형식이라 표준 JSON 검증은 통과하지 못할 수 있습니다.
